Six corrections at a glance

  1. Fill — "refund" assigned as major_category for the 123 refunded rows.
  2. Fill — 113 missing merchant_name values populated (all ATM withdrawals).
  3. Drop — 21 fast-food / grocery rows with |amount_value| > €100,000.
  4. Drop — 5 zero-amount finance stubs.
  5. Drop — 118 duplicate rows sharing a ref_id.
  6. Transform — fees converted from cents to euros.

Overview — cleaning funnel

The six corrections split into three families — filling (steps 1-2, no row removed), row removal (steps 3-5, 144 rows), and unit transformation (step 6, no row removed). Note that step 5 removes only 118 duplicate ref_id rows (not 120) because two of the duplicate pairs — BUFFALO GRILL −€322,255 and WAFFLE FACTORY −€114,073 — were both fully consumed by the §3 outlier filter, so step 5 had nothing left to de-duplicate for those ref_ids.

Step-by-step

1

Add "refund" as the major_category for refunded rows

Every one of the 123 rows with a missing major_category had status = refunded and minor_category = refund. "refund" was assigned as the canonical major-category for those rows.

mask = df['major_category'].isna() & (df['status'] == 'refunded')
df.loc[mask, 'major_category'] = 'refund'    # 123 rows filled

Result: zero missing values in major_category, and refunds are now a visible category in dashboards instead of a null bucket.

The "(missing)" bar on the raw side is now a labelled "refund" bar in the cleaned data. The slight drop in restaurants/groceries is the §3 outlier removal.

2

Fill missing merchant_name using merchant_id

All 113 missing merchant_name rows share the same characteristics: minor_category = atm, title = "RETRAIT DAB", and each row has a unique merchant_id (one per ATM terminal). A lookup table was built from the 2,789 rows that already have both merchant_id and merchant_name populated, then used to fill the blanks:

id_to_name = df[df['merchant_name'].notna()].drop_duplicates('merchant_id') \
                                            .set_index('merchant_id')['merchant_name']
df['merchant_name'] = df['merchant_name'].fillna(df['merchant_id'].map(id_to_name))
# Fallback for IDs not seen elsewhere → use `title` (which equals merchant_name 100% of the time)
df['merchant_name'] = df['merchant_name'].fillna(df['title'])
3

Remove |amount_value| > €100,000 on fast-food / grocery merchants

All 21 rows that match both conditions were flagged. None had a plausible real-world amount — McDonald's, Burger King, Buffalo Grill etc. don't take €100k+ single payments.

mask = (df['amount_value'].abs() > 100_000) & \
       (df['major_category'].isin(['restaurants_bars_cafes', 'groceries']))
df = df.loc[~mask]    # removed 21 rows

The long upper tail past 105 (i.e. above €100k) is gone in the cleaned distribution. The cleaned max |amount| is just under €80k and sits in travel/finance, which is at least plausible for a hotel booking or large transfer.

4

Remove zero-amount transactions

Five rows had amount_value = -0.0, all in major_category = finance and mostly with a null merchant. These looked like malformed stubs — no economic value and no clear reporting purpose — and were dropped.

df = df.loc[df['amount_value'] != 0]    # removed 5 rows
5

De-duplicate ref_id (keep the first row per ref_id)

In the raw data, 120 ref_id values appeared twice (240 rows involved). Within each pair member_id, merchant_id, amount_value, created_at and status all matched — only transaction_id differed. These are the same real transaction ingested twice and would double-count in any aggregate.

df = df.drop_duplicates(subset='ref_id', keep='first')    # removed 118 rows
# (Not 120 — two of the duplicate pairs were already fully removed by step 3.)

Result: ref_id is now unique across the whole table.

6

Convert fees from cents to euros

The fees column was divided by 100 in-place and kept its name — the unit is now EUR, matching amount_value.

df['fees'] = (df['fees'] / 100.0).round(2)

Same seven distinct tariff levels on both sides — just rescaled. The max fee is now a sensible €40.00 (foreign-exchange / instant-transfer) rather than an apparent €4,000.

Missing values — recap

All three previously-affected columns are addressed. merchant_name and major_category are now 100% populated; pfm_recurring_frequency remains sparse by design — only recurring subscription charges are tagged, and the raw dataset only ever observed monthly as the non-null value.
